# 04 - UX 監査（Unity Visual Scripting との比較）

ゲームの大まかな流れを組む作業を、Unity Visual Scripting（State Graph / Script Graph）より明らかに簡単にするための現状調査。
評価はシナリオで行う（見た目の作り込みではなく、手数・迷う所・ウィンドウの行き来で測る）。

- **シナリオ A（5 分）**: このツールを初めて使う人が、ドキュメントを読まずに新しいグラフを作り、
  Title シーン → Game シーン → Result シーン → Title に戻る流れを、各段階をボタンで進むように組み、Play する
- **シナリオ B**: そのグラフで、Game の流れの中に Pause ステートを（コンテナで）足し、Result から Retry する道を足して、
  Play 中に今どこにいるかを確かめる

## 調査の方法と前提

- 対象: 0.9.1（`main` の `e7ed5a0`）
- **この監査は、コードと UXML / USS を 1 手ずつ確かめながら画面の動きをたどった机上の通し（コグニティブ・ウォークスルー）**で、
  実際にエディタを操作して時間を計ったものではない。所要時間は手数からの見積もり。実機での計測は改善後の比較のときに行う（未決事項参照）
- シーンアセット（Title / Game / Result）と、各シーンの UI Button そのものは既にあるものとする（どちらのツールでも同じ手間なので数えない）。
  数えるのは「グラフを作る」「ボタンをグラフに繋ぐ」「Play できるようにする」手数
- 1 手 = 1 回のクリック・ドラッグ・メニュー選択・入力（1 つの欄への入力は 1 手）
- 比較対象の画面: `docs/images/1791466521798_image.webp`（State Graph。新規作成直後で、緑の帯の Start ステートがある）、
  `docs/images/1791466533312_image.webp`（Start ステートの中の Script Graph。On Enter State / On Update / On Exit State が最初から置かれている）

## 気付いた点と Unity State Graph の比較

判定: ◎ = こちらが明らかに良い、○ = 同等、△ = こちらが劣る / どちらも悪い

| ID | 本ツール（0.9.1） | Unity State Graph | 判定 |
|---|---|---|---|
| F1 | 新しいグラフは空。Entry が無いと Error だが、一覧は閉じていて理由が見えない | 新規作成時に緑の帯の **Start** ステートが最初からある（画像 1） | △ |
| F2 | 空のキャンバスに案内が無い（追加は Space / 右クリック → Create Node） | 同じく案内は無いが、Start があるので右クリックすれば分かる | △ |
| F3 | Scene ノードのタイトルは既定で「Scene」。シーン名は 2 行目のサマリー | ステートのタイトルは Graph Inspector で手入力。シーンという概念は無い | ○ |
| F4 | シーンは選んだノードのインスペクタへドラッグする（キャンバスへは落とせない） | シーンを読むには、ステートの Script Graph に Load Scene を置き、**シーン名を文字列で入力** | ◎（だがもっと短くできる） |
| F5 | ポートから空き地へエッジを落としても何も起きない | Script Graph では空き地へ落とすと検索が開き、作って繋がる | △ |
| F6 | Event は四角い箱で、タイトル「Event」・イベント名は 2 行目 | 遷移は名前の無い小さな六角形。何で遷移するかは中の Script Graph を開かないと分からない | ◎（だが箱がステートに見える） |
| F7 | イベント名は自由入力。ボタン側でもう一度入力し、食い違いは検出しない | Custom Event の名前も文字列で二重入力 | ○（どちらも悪い） |
| F8 | シーン未設定・Entry 無しなどは警告・エラーになるが、直すボタンは無い | 同じく無い | ○ |
| F9 | 「Add Scenes to Build」は 1 手だが、順番（index 0）は保証しない。Play は今開いているシーンから始まる | Build Settings は手作業 | ○ |
| F10 | Runner の設置はシーンで 8 手。何が要るかを UI が教えない | State Machine コンポーネント・Embed / Graph の選択・アセットの指定。さらに DontDestroyOnLoad は自分で用意 | ○ |
| F11 | 別シーンのボタンから Raise するにはコードが要る | On Button Click はボタンの参照が要り、別シーンからは同じく不可 | ○（どちらも悪い。こちらが先に解ける） |
| F12 | ツールに Play ボタンは無い | 同じく無い | ○ |
| F13 | 既存のノードをコンテナへ移すと、切り取りでエッジが消える | Super State へのコピーも遷移は付いてこない | ○ |
| F14 | 空のコンテナに案内なし。Entry / Exit / 出口の考え方を知っている必要がある | Super State の中は Start があるだけ。出口の概念は無い（外の遷移で出る） | ○ |
| F15 | Play 中は現在のノードが緑になるだけ。イベントを起こせない・値が見えない・経路が残らない | 実行中のステートが光る。変数は Inspector で見られるが、遷移を手で起こす手段は無い | △ |
| F16 | Root ではコンテナが緑。中はダブルクリックで見る | Super State も同じ | ○ |
| F17 | 問題一覧は既定で閉じている（新しい Error が出たときだけ開く） | 警告の一覧は無い | ◎ |
| F18 | 同じシーンの Scene ノードへ戻っても読み直さないが、表示されない | 該当なし | △ |

まとめ:
- 既に勝っている所: シーンをアセットで指定できる（F4）、遷移のイベント名が見える（F6）、検証と問題一覧（F17）、コンテナの出口に名前がある、
  Runner が DontDestroyOnLoad と重複防止を持っている（F10）
- 負けている・どちらも悪い所: 最初の一歩（F1, F2）、エッジからの作成（F5）、**ボタンを繋ぐのにコードが要る（F11）**、Play までの準備（F9, F10, F12）、
  Play 中の確認（F15）、名前の二重入力（F7）
